# Task4 — продажа ОСАГО (заметки к схеме)

Файл дополняет диаграмму `Task4/InsureTech_container_to-be.drawio` и фиксирует принятые решения.

## Поток ОСАГО (пользовательский сценарий)
- Пользователь заполняет данные авто и запускает расчёт ОСАГО.
- Система запрашивает предложения у всех доступных страховых и **показывает их по мере поступления**, не дожидаясь всех.
- Максимальное ожидание ответа **от каждой страховой — ≤ 60 секунд**.
- Пик: до **2500 одновременных пользователей**, запускающих ОСАГО-расчёт.

## Сервисы и ответственность
- **`core-app`**:
  - принимает запрос от веб-приложения,
  - инициирует процесс расчёта ОСАГО,
  - агрегирует/хранит результаты для UI,
  - стримит предложения пользователю.
- **`osago-aggregator`**:
  - отправляет заявки в страховые,
  - опрашивает страховые по заявке (create + get offer),
  - отдаёт результаты обратно в `core-app`.

## Нужно ли хранилище `osago-aggregator`?
Да. **`osago-aggregator-db`** хранит:
- `quoteRequestId` ↔ insurerRequestId,
- статусы по каждой страховой,
- дедлайны/TTL (60s),
- данные для идемпотентности и безопасных повторов.

## Интеграция core-app ↔ osago-aggregator
Выбрана **асинхронная интеграция через Kafka**, чтобы не блокировать `core-app` и управлять нагрузкой.

### Topics (пример контрактов)
- `osago.quote.requested` — команда/событие на старт расчёта (core → osago-aggregator).
- `osago.offer.received` — предложение от конкретной страховой (osago-aggregator → core).
- `osago.offer.timeout` — истёк дедлайн на страховую (osago-aggregator → core).

## API для веб-приложения
- **REST** для старта процесса:
  - `POST /osago/quotes`
- **SSE** для отображения офферов “по мере поступления”:
  - `GET /osago/quotes/{id}/events`

### Учёт нескольких реплик core-app (SSE)
SSE — долгоживущее соединение. При нескольких репликах `core-app` нужны:
- **sticky sessions** на ingress, или
- stateless SSE: хранить офферы/статусы в общем хранилище по `quoteRequestId` и стримить из него.

## Паттерны отказоустойчивости (где применяем)
- **core-app**:
  - **Rate Limiting** (учитывая до 2500 concurrent),
  - **Timeout** для REST и SSE (SSE допускает переподключение).
- **osago-aggregator → страховые**:
  - **Timeout ≤ 60s** (дедлайн на страховую),
  - **Retry + backoff** (только для безопасных/идемпотентных операций),
  - **Circuit Breaker** (не “ронять” агрегатор из‑за одной страховой),
  - **Rate Limiting** (per-insurer и общий лимит).
- **потребление событий**:
  - **идемпотентность** (возможны повторы доставки сообщений).
